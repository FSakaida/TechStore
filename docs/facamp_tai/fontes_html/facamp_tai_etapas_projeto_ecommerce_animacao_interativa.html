6. Atores, dores e metas do negócio

Cliente

Quer encontrar produtos, saber preço e concluir a compra com facilidade.

Operação

Precisa controlar estoque, pedidos e clientes sem retrabalho.

Gestão

Deseja relatórios básicos de vendas, volume e produtos mais vendidos.

TI/Desenvolvimento

Precisa de um escopo claro para modelar dados, programar telas e testar o fluxo.

Dor típica 1

Perda de controle do estoque ao registrar vendas manualmente.

Dor típica 2

Duplicidade de dados ou pedidos inconsistentes por falta de regras.

Leitura prática: um requisito mal definido gera tabelas erradas, código redundante e falhas de negócio mais adiante.

21. Criação das tabelas e constraints

CREATE TABLE produtos (
  id SERIAL PRIMARY KEY,
  nome VARCHAR(140) NOT NULL,
  descricao TEXT,
  preco NUMERIC(10,2) NOT NULL CHECK (preco >= 0),
  estoque INTEGER NOT NULL DEFAULT 0 CHECK (estoque >= 0),
  categoria_id INTEGER NOT NULL REFERENCES categorias(id)
);

PRIMARY KEY

Identifica unicamente cada registro.

FOREIGN KEY

Conecta as tabelas entre si.

CHECK

Evita preço e estoque negativos.

NOT NULL/UNIQUE

Asseguram campos obrigatórios e unicidade onde necessário.

22. Índices e organização física

Índices por nome

Ajudam em buscas e ordenações do catálogo.

Índices por relacionamento

Aceleram histórico de pedidos e consulta de itens.

Custo da indexação

Índices aceleram leitura, mas também aumentam o custo de escrita.

Ferramentas de análise

Use EXPLAIN no PostgreSQL e o plano gráfico no DBeaver/pgAdmin.

CREATE INDEX idx_produtos_nome ON produtos(nome);
CREATE INDEX idx_pedidos_cliente ON pedidos(cliente_id);
EXPLAIN SELECT * FROM produtos ORDER BY nome;

29. Modelos ORM e acesso ao PostgreSQL

app.config["SQLALCHEMY_DATABASE_URI"] = os.getenv(
  "DATABASE_URL",
  "postgresql+psycopg://postgres:postgres@localhost:5432/ecommerce"
)
db = SQLAlchemy(app)

class Produto(db.Model):
    __tablename__ = "produtos"
    id = db.Column(db.Integer, primary_key=True)
    nome = db.Column(db.String(140), nullable=False)
Prática recomendada: a string de conexão deve vir de variável de ambiente para que o mesmo código rode localmente e na cloud.

32. Transações, testes e segurança — visão geral

Motivação

Objetivo

Garantir qualidade funcional e proteção mínima das informações.

Ferramentas

pytest, Postman, logs da aplicação e recursos do PostgreSQL.

33. Passo a passo da transação de checkout

1Abrir transação
2Criar pedido
3Inserir itens
4Atualizar estoque
5Validar falhas
6Commit ou rollback
try:
    pedido = Pedido(cliente=cliente, status="CRIADO")
    db.session.add(pedido)
    # itens + estoque
    db.session.commit()
except Exception:
    db.session.rollback()

35. Segurança mínima da aplicação

Senhas

Armazenar apenas hash, nunca texto puro.

Segredos

Guardar DATABASE_URL e SECRET_KEY em variáveis de ambiente.

Validação

Validar entrada no formulário e no banco.

Privilégios

Aplicação usa usuário próprio no PostgreSQL, não superusuário.

Logs

Registrar erros sem expor credenciais.

Dados pessoais

Evitar dados reais nas atividades acadêmicas.

from werkzeug.security import generate_password_hash
senha_hash = generate_password_hash(senha_digitada)

36. Backup, restauração e observabilidade

Backup lógico

Exportar estrutura e dados com pg_dump.

Restauração

Testar a recuperação com pg_restore ou scripts SQL.

Logs da app

Inspecionar erros de execução, rotas e exceções.

Monitoramento simples

Acompanhar se a aplicação sobe, responde e grava pedidos.

pg_dump -U ecommerce_user -d ecommerce > backup.sql
Essencial: backup só é confiável quando a restauração também é testada.
